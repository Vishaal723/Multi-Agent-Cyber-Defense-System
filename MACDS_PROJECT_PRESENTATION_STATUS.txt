PROJECT PROGRESS, FEATURES, VERIFIED FIXES, AND NEXT STEPS
Status date: 12 October 2026

======================================================================
1. PROJECT OVERVIEW
======================================================================

MACDS is a local demonstration application for cybersecurity monitoring,
incident workflows, and classical AI algorithm demonstrations. It is not
currently connected to a production network or real security appliances.

Architecture:
- Frontend: React 19 and Vite; JavaScript source in frontend/src.
- Backend: Python FastAPI; REST routes and a WebSocket telemetry feed.
- Storage: SQLite. The normal default remains backend/data/macds.db.
- Safe database option: set MACDS_DB_PATH before starting the backend to
  select a separate SQLite file. This preserves the normal default behavior.
- Local development: backend on 127.0.0.1:8000; frontend on
  localhost:5173, with Vite proxying /api and /ws to the backend.

The codebase contains nine agent implementations:
Coordinator, Network Monitoring, Intrusion Detection, Threat Correlation,
Knowledge Base, Reasoning, Planning, Response, and Learning.

3. FEATURES PRESENT IN THE APPLICATION
======================================================================

- Dashboard with persisted threat/incident summaries, severity counts,
  recent incident links, and clearly labeled synthetic network telemetry.
- Live Monitoring view with configured topology traversal, generated packet
  stream, traffic statistics, and device status/quarantine controls.
- Threat and incident views, with investigation details and response flows.
- Attack Simulator with six synthetic scenarios and a seven-stage trace:
  brute force, ransomware, SQL injection, DDoS, DNS tunneling, and port scan.
- AI Algorithms Lab:
  BFS/DFS topology traversal; A* on a fixed response-state graph;
  hill climbing on a synthetic fitness function; fixed attacker/defender
  payoff evaluation; CSP backtracking; forward and backward chaining.
- Knowledge Base and rule management with rule search, editing/versioning,
  and a static MITRE ATT&CK reference mapping.
- Agent configuration/status records, reports, audit logs, settings, and
  user/role management.
- SQLite persistence for application users, agent records, rules, threats,
  incidents, responses, devices, audit logs, and feedback metrics.

5. LIMITATIONS AND WORK STILL TO IMPLEMENT
======================================================================

DATA AND INTEGRATIONS
- Packet and traffic telemetry are generated demo data, not captured from
  a physical network or production monitoring feed.
- Response actions update MACDS records/configuration; they do not operate
  real firewalls, endpoints, switches, or user accounts.
- Simulator activity is synthetic but persists to its configured SQLite
  database. Use a disposable database for demonstrations and tests.
- Email/chat notification and enterprise cloud/SIEM integrations are not
  connected to external services.

ALGORITHM AND ANALYTICS SCOPE
- Topology search uses a configured graph, not live network discovery.
- A* uses a fixed response-state model; hill climbing uses a synthetic
  fitness function; Game Theory evaluates fixed payoffs for one attacker
  action; CSP returns a valid assignment using backtracking.
- Forward/backward reasoning uses configured rules and goal dependencies.
  These are demonstrations, not a trained or general-purpose reasoning
  platform.
- MITRE content and recommendation examples are static reference/demo data.
- Incident resolution rate is a ratio of persisted incidents marked
  Mitigated or Closed to all persisted incidents; it is not a measured
  security-detection accuracy metric. MTTD/MTTR are unavailable because the
  current data model does not store reliable measured durations.
- Rule Testing Sandbox performs local category/keyword matching against
  simulated payload text; it is not a production rule deployment or a full
  backend rule-engine test.

SECURITY AND PRODUCTION READINESS
- Several read/write API routes and the WebSocket do not enforce
  authentication consistently; audit/API exports also need authorization
  review.
- The current authentication implementation uses a development JWT secret
  fallback and unsalted SHA-256 password hashing. CORS is permissive.
- Do not expose this local demo to untrusted networks or describe it as
  production-secure before a dedicated security-hardening effort.

7. LOCAL STARTUP FOR A SAFE DEMONSTRATION
======================================================================

Open two PowerShell terminals. The first starts the backend with a unique
temporary database so simulator actions do not write to the normal project
database:

    $env:MACDS_DB_PATH = Join-Path $env:TEMP ("macds-demo-" + [guid]::NewGuid().ToString("N") + ".db")
    Set-Location F:\FOAI\backend
    python -m uvicorn main:app --host 127.0.0.1 --port 8000

In the second terminal, start the frontend. npm.cmd avoids PowerShell's
script execution-policy error for npm.ps1:

    Set-Location F:\FOAI\frontend
    npm.cmd run dev -- --host 127.0.0.1 --port 5173

Open http://localhost:5173. Stop each service with Ctrl+C in its terminal.
The selected disposable SQLite path is shown by:

    $env:MACDS_DB_PATH

When MACDS_DB_PATH is not set, the backend uses its existing default
backend/data/macds.db. Do not run database-mutating demos or tests against
that default if the database contains user data.
